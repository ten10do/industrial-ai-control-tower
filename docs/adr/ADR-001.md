# ADR-001: Monorepo Architecture

## Status

Accepted

## Context

The Industrial AI Control Tower consists of multiple interacting components: backend API, frontend UI, equipment simulator, documentation, and infrastructure definitions. We needed a repository structure that supports cross-component development without multiplying operational overhead.

## Decision

Use a single monorepo at `industrial-ai-control-tower/` with top-level directories for backend, frontend, simulator, docs, tests, scripts, and infra.

## Alternatives

- **Polyrepo**: One repository per component. Cleaner ownership boundaries, but higher coordination cost for API contract changes and shared documentation.
- **Monorepo with shared packages**: More scalable for large teams, but adds build tooling complexity (e.g., Nx, Turborepo) that is unnecessary for Phase 0.

## Consequences

- API contracts, ADRs, and domain documentation live next to the code they describe.
- CI can validate backend, frontend, and docs in a single pipeline.
- Boundaries between components must be enforced by convention and review rather than repository separation.
- The structure can be migrated to a more sophisticated monorepo tool later if team size grows.
