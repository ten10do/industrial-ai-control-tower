# ADR-002: FastAPI Backend

## Status

Accepted

## Context

The backend must expose a REST API, support asynchronous request handling, provide automatic API documentation, and integrate cleanly with Pydantic for validation and SQLAlchemy for persistence.

## Decision

Use FastAPI as the backend framework.

## Alternatives

- **Django**: Mature ecosystem, but heavier and more opinionated than needed for an API-first service.
- **Flask**: Flexible, but lacks built-in async support and automatic OpenAPI documentation.
- **Starlette directly**: Possible, but FastAPI adds Pydantic integration and documentation generation with minimal overhead.

## Consequences

- Automatic OpenAPI/Swagger documentation at `/docs`.
- Native async support for future I/O-bound agent and industrial integration workloads.
- Strong typing through Pydantic models across API, service, and persistence layers.
- Smaller ecosystem than Django for admin and authentication; those must be built or integrated later.
