# ADR-009: LLM Provider Abstraction

## Status

Provisional — to be confirmed in Phase 5

## Context

The platform will use LLMs for diagnosis, planning, and knowledge retrieval. Different deployments may prefer different providers, models, or hosting strategies (cloud, private, on-premise).

## Decision

Introduce a provider abstraction layer so agent code depends on an interface, not a specific LLM implementation.

## Alternatives

- **Single hard-coded provider**: Simplest, but creates vendor lock-in and complicates testing.
- **Direct LangChain calls everywhere**: Flexible, but scatters provider details across agents.

## Consequences

- Agents request completions through a common interface.
- Provider selection and model configuration are centralized.
- Structured output schemas are enforced independent of the underlying model.
- Supports mocking for unit tests and safety tests.
